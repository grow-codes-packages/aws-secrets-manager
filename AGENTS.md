# AGENTS.md — Grow Codes SDK for AWS Secrets Manager (`aws-secrets-manager`)

Instructions for AI coding agents and humans working in this repository. `CLAUDE.md` is a symlink to
this file. Service-specific notes (vendor quirks, API coverage, emulator limits) live in
`docs/compatibility.md`, the README "Function overview" and `skills/aws-secrets-manager-sdk/SKILL.md`.

## What this repository is

One API for AWS Secrets Manager in five languages, generated from
[sdk-kit](https://github.com/grow-codes-packages/sdk-kit) (version in `.sdk-kit.json`) and
completed with service code. Categories: **secrets**. The contract for every package is the
sdk-kit specification (`SPEC.md` in sdk-kit): names, defaults, error codes, environment variables,
category interfaces and the Docker contract.

## Generated files rule

- A file whose first lines contain `Generated by sdk-kit <version> — do not edit` belongs to sdk-kit.
  **Do not edit it here.** Change sdk-kit (template), release it, then run `sdk-kit sync` in this
  repository. A local edit is detected (`.sdk-kit.json` keeps a SHA-256 per file) and blocks the
  next sync until it is reverted or forced.
- To take over a generated file for good, delete its header line; sync then leaves it alone.
- Never edit `conformance/` or `.sdk-kit.json` by hand.
- `sdk-kit check` (run in CI) verifies that the required files, badges and workflows are present.

## API parity rule

The five packages expose the **same** functions, options, defaults, error codes and behaviour. Any
change to the public API lands in all five languages in the same pull request, with unit tests in
each and an integration call in the Docker suite. Names follow each language's convention:

| | TypeScript | Rust | Go | Python | Java |
| - | - | - | - | - | - |
| Methods | `camelCase` | `snake_case` | `PascalCase`, `ctx` first | `snake_case` | `camelCase` |
| Errors | `AwsSecretsManagerError` + subclasses | `Error` enum, `code()` | `*Error`, `errors.Is(err, awssecretsmanager.ErrNotFound)` | `AwsSecretsManagerError` + subclasses | `AwsSecretsManagerException` + subclasses |
| Durations | `…Ms` numbers | `Duration` | `time.Duration` | seconds (`…_s`) / `timedelta` | `Duration` |
| Async | `Promise` + `AbortSignal` | `async` + `blocking` feature | sync with `ctx` | sync + `AsyncAwsSecretsManagerClient` | sync + `…Async` |

If one language truly cannot support something, document it in `docs/compatibility.md`.

## Tests and coverage

- Unit tests run against local mock HTTP servers; they never need network access or Docker.
- **Coverage gates** (CI-enforced, first-party code only): TypeScript, Python and Java ≥ 90 % lines
  **and** ≥ 90 % branches; Rust ≥ 90 % lines and ≥ 90 % regions; Go ≥ 90 % statements.
- Unit conformance tests are named after the ids in `conformance/core-unit.md`.
- Test fakes for users of the package ship in the testing module (TypeScript
  `@grow-codes/aws-secrets-manager/testing`, Rust feature `testing`, Go `testkit`, Python
  `grow_aws_secrets_manager.testing`, Java `codes.grow.packages.awssecretsmanager.testing`).

## Docker integration rules

- `docker/compose.yml` runs `motoserver/moto:5.2.4` plus a one-shot `bootstrap` service that writes credentials
  to `/bootstrap/env`. Tests read that file and `GROW_AWS_SECRETS_MANAGER_URL`.
- Each language has a `test-<lang>` service (profile `<lang>`). Its Dockerfile packs the package and
  installs it into the consumer project in `<lang>/integration/`, which runs the integration tests
  and the conformance runner.
- Always run through `make test-docker`: it uses a unique Compose project per run, publishes no host
  ports and always runs `docker compose down -v`, even on failure or Ctrl-C.
- Every public function is called at least once against the real service with a round-trip
  assertion. Functions the service cannot serve are listed in `docs/compatibility.md` and covered by
  unit tests.

  `CHANGELOG.md` by hand. Use the language as the scope when a change touches one package.
- One release pull request covers all five packages. Tags: `typescript-vX.Y.Z`, `rust-vX.Y.Z`,

## AWS Secrets Manager specifics

- **Transport = official AWS SDK** of each language (SPEC exception for cloud SDK services, binding
  decision): TypeScript `@aws-sdk/client-secrets-manager` v3 with an undici handler that reuses the
  core dispatcher; Rust `aws-sdk-secretsmanager` + `aws-config` (no default features) with an own
  `reqwest`/rustls HTTP client and an interceptor; Go AWS SDK v2 with the Grow HTTP client and
  middleware; Python `boto3` (sync) and `aioboto3` (async, optional extra `[async]` with the pinned
  boto3 window — sync users keep an unpinned boto3); Java AWS SDK v2 with an own `java.net.http`
  `SdkHttpClient` and an `ExecutionInterceptor`. Retries: AWS SDK standard mode,
  `maxAttempts = maxRetries + 1`. Never write own SigV4 or HTTP code for AWS calls.
- **Fixture** (`docker/compose.service.yml`): `motoserver/moto:5.2.4` (pinned by digest, test-only,
  IAM auth on with `INITIAL_NO_AUTH_ACTION_COUNT=3`) and a `curlimages/curl` bootstrap
  (`curl --aws-sigv4`) that spends the 3 free actions on an admin IAM user + key, then creates a
  read-only user and two seed secrets and writes `/bootstrap/env` (`AWS_*`,
  `GROW_AWS_SECRETS_MANAGER_URL`, `GROW_TEST_READONLY_*`, `GROW_TEST_SEED_*`,
  `GROW_TEST_EMULATOR=moto`). Nothing may call AWS before the bootstrap; a stack whose admin key
  was lost must be recreated (`down -v`).
- **Error mapping by AWS error code**, HTTP status only as the fallback (AWS answers 400 for
  throttling and access denied). Moto answers 404 for not-found and 403 **XML** for IAM errors:
  403 without a known code → `AUTHENTICATION` if the body mentions `InvalidClientTokenId`,
  `SignatureDoesNotMatch` or `security token`, else `PERMISSION_DENIED`. HTML 500 for
  `validateResourcePolicy` → `UNSUPPORTED`. Keep the code table identical in all five languages
  (`docs/compatibility.md`).
- **Parity decisions** (binding, all five languages; `docs/compatibility.md`): env prefix
  `GROW_AWS_SECRETS_MANAGER_*` > `AWS_*`; GROW/AWS static credentials are one set, never mixed;
  `health()` probe `min(requestTimeout, 5 s)`, no retries, auth failures and other 4xx = `ok` with
  details; `serverVersion()` → `UNSUPPORTED`; `deleteSecret` rejects window + force and windows
  outside 7–30 client side, unset = AWS default; provider `delete` uses `recoveryWindowDays`
  (default 30) unless `permanent`, `versions` and `cas` → `VALIDATION`; `getJsonField` exact key
  first, then dot path, JSON `null` = absent; `AwsSecretCache` (TTL 1 h, 1 024, stage-aware,
  `DescribeSecret` check) plus `awsDefaults()` for the generic cache; any call on a closed client
  → `CANCELLED`.
- **Integration tests on Moto**: read back with an explicit `versionStage: "AWSCURRENT"` after
  moving a stage (Moto's default read is stale), use a dedicated secret for rotation (Moto has no
  Lambda; `cancelRotateSecret` needs a recorded Lambda ARN), do not batch-read a secret whose
  `AWSCURRENT` moved (Moto fails the whole `BatchGetSecretValue`), and assert codes, never Moto's
  message text. Unit-test only: `validateResourcePolicy` result, Lambda rotation, assume-role (STS
  mock), throttling / `Retry-After`, AWS-exact error shapes.
- **Live checks** against the AWS sandbox accounts are optional; temporary resources must be tagged
  `grow:purpose=sdk-live-test` and deleted when the job ends.

## Rules for agents

- Keep secrets out of code, tests, fixtures, logs and commit messages. Credentials are always wrapped
  in the redacting secret type; error messages pass through redaction.
- Runtime dependencies must use a licence from the allowlist: Apache-2.0, MIT, BSD-2-Clause,
  BSD-3-Clause, ISC, Zlib, Unicode-3.0, Unicode-DFS-2016, 0BSD, CC0-1.0, MPL-2.0 (Java also MIT-0
  for `org.reactivestreams:reactive-streams`, pulled in by the AWS SDK core). Never GPL, LGPL,
  AGPL, SSPL, BUSL or EPL at runtime.
- Keep dependencies small; prefer the standard library.
- Before you push: `make lint coverage` for every language you touched (or all of them for shared
  changes), and `make test-docker LANGS="<lang>"` when behaviour against the service changed.
- Update the README function overview, `docs/` and the skill file when the public API changes.
